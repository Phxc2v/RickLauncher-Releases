# What's new in RickLauncher

> Plain-language notes on what changed in each version.

## 1.3.1

- 🧷 **A second copy of the launcher no longer takes the first one's data.** With two launchers on one PC — say a portable copy and an installed one — whichever started next pulled the other's games, profiles, saves and mod library across to itself. Nothing was lost, but the first copy suddenly looked empty and the second showed "someone else's" games. Each launcher now marks its own storage, and another one's can only be adopted if that installation is genuinely gone.

- 📦 **There is an installer now.** The launcher used to exist only as an archive: download it, find it, unpack it, don't lose the folder. GitHub releases now carry `RickLauncher-Setup.exe` next to the archive — a normal install with shortcuts and an "Apps & features" entry. It never asks for administrator rights: it installs into your own user folder, because all launcher data (profiles, saves, mod library) lives next to the program and has to stay writable — otherwise automatic updates would break. The archive stays for portable installs, and it is still what the launcher downloads when it updates itself. Uninstalling asks whether to delete your data, and **keeps** it by default.

- ♥ **A "Donate" button.** The launcher is free and stays free, but release hosting and the download mirror cost money. The button sits in the top bar next to the version and in the menu — nothing pops up over your game. The window offers two routes to the same page: a normal web page in your browser (no Telegram needed, pay by card) and the same page inside Telegram. A QR code is there too, so you can point your phone's camera at it and pay from the phone. The address can be copied and checked: the page always opens in your own browser, never inside the launcher.

## 1.3.0

**Security**
- 🛡️ **A pack can no longer make the launcher run something.** Links inside a pack ("mod page", "read more") used to be handed to Windows as-is — and Windows will happily run a program from disk or the network for such a link, not just open a website. The launcher now opens web addresses and Steam/Nexus links only, and refuses the rest with a message.
- 🔒 **Mods fetched over an unencrypted connection need your consent.** Such a file can be swapped in transit, and the launcher deliberately clears its "downloaded from the internet" mark so the game will load it. The install window now spells out which mods come over http and from which sites, and the install won't start until you tick the box. None of our own packs contain such mods.
- 🚫 **Runnable files are no longer unpacked from mod archives** (.exe, .bat, .ps1 and the like) — a mod is data plus .dll, nothing else belongs there. Archives that try to write outside the mod folder, or that unpack to an absurd size, are refused as well.
- 🧾 **If something is wrong with a mod's archive, the launcher says so and asks.** Suspicious files used to be skipped in silence, leaving an install that looked fine while the mod was incomplete. You now see which mod, which archive, where it was downloaded from and what was found — and decide whether to carry on or stop the whole install.
- 🔐 **A stored Nexus key and Steam sign-in are encrypted more tightly.** Encryption is now bound to your Windows account AND to this particular PC, so a settings file leaked through OneDrive or a backup is useless elsewhere. The Nexus key is no longer shown in clear text in Settings.

**Ready-made mod packs**
- 🗂️ **Packs are now picked from a list instead of a file-open dialog.** Installing a ready-made pack used to require knowing three things a player doesn't: that packs exist at all, where the file lives, and which of several matches their game. Now a window lists them — each with a title, description, picture, game version and mod count — and one click installs it. Only packs built for a game version **you actually have installed** are listed, so a 1.2 pack can't land on 1.4 by accident. When the same pack is released for several game versions it's **one card with a version picker**, not three separate ones — the picker opens on the version that fits your game, and the mod count updates as you switch. "Open a pack file…" is still there at the bottom, for your own and downloaded packs.
- 🎁 **After a launcher update the list appears once, by itself.** A new build usually brings new or updated packs, and nobody goes hunting through a menu for them. Shown exactly once per version, and only when at least one pack fits your game.
- 🖼️ **A pack's picture no longer falls apart when the window is resized.** The artwork used to sit in a full-width strip of fixed height: the wider the window, the more it was zoomed, until all that was left of an ordinary picture was a band across its middle — no title at the top, no bottom half. The cover now has two layouts, and the pack's author picks one right in the editor. **"Card on the left"** shows any picture whole, whatever its proportions — nothing is cropped, nothing needs preparing, and the panel around it is filled with a blurred copy of the art. **"Wide header"** is that full-width strip, but for artwork prepared at 1620×540: the editor adds a "what stays in frame" slider and a preview of exactly what the player will see. Packs made earlier show as a card, so their artwork isn't cropped by anything any more. Pictures in the pack list are shown whole too.
- ✅ **The editor checks a pack before exporting it.** These used to be the player's problem: a mod with no id, two mods sharing an id (they overwrote each other), a mod with no version (so the launcher can't reuse a copy already on disk and re-downloads it every time), a mod with no checksum (nothing verifies the download), an http source. The author now gets the list up front — serious problems block the export, the rest warn and ask.
- 🖼️ **Screenshots in the editor are shown as pictures rather than paths,** and each has a "Make the cover" button — the commonest mistake (the cover picture ending up in the screenshot list) is now one click to fix.
- ⚙️ **The editor no longer rolls back the launcher's settings.** Both keep settings in one file, and closing the editor could restore them to how they were when it opened — a Steam sign-in made in the meantime, for instance, would vanish. Each side now writes only what it actually changed.
- 🔎 **The editor no longer loses pictures silently.** Pictures are stored in a pack project as paths, so if the file was later renamed or deleted — or the project moved to another PC — the path stayed in the box, everything looked fine, and on export the picture simply vanished: the pack shipped with no cover and no way to tell why. The editor now looks for a missing file next to the project itself, and if it isn't there says exactly which file is gone and asks before exporting without it.
- 📸 **A pack's screenshots are finally visible.** Authors could attach them in the editor before, but the launcher showed them nowhere — they just sat inside the pack file as dead weight. There's now a thumbnail strip under the description, and clicking one opens it at full window size.
- 🪶 **Pictures inside a pack are compressed automatically.** An ordinary PNG screenshot is a couple of megabytes, so one picture blew a pack up from 6 KB to 2 MB. On export every picture (PNG, BMP, JPG) is now re-encoded as JPEG at 80% quality and scaled to a sensible size: those 2 MB become ~160 KB, with no visible difference. If re-encoding wouldn't actually save anything, the original file is kept.
- 🔐 **The launcher warns about accounts BEFORE the download starts.** If a pack contains Steam Workshop or Nexus mods and you aren't signed in, the install window says so up front — with how many such mods there are and a button to sign in. Previously the install ran happily through the free mods and only then stopped at the first one it couldn't fetch. You can still install without signing in: those mods are marked "download manually" and everything else installs as usual.

**Installing packs**
- 🔢 **Updating a mod no longer breaks the load order.** A mod already in the list did not always stay where it was on a re-install or an update: the launcher re-picked its slot "by the rules" and lifted it up — so a pack installed with the author's carefully arranged order came out rearranged after a single mod update, and the launcher then offered to re-sort it. A slot is now picked only for a NEW mod; one already in the list is left alone. The pack file's load order is also applied to the profile exactly as the author arranged it.
- ❓ **Closing the window mid-install now asks first.** A stray click on the ✕ used to abort the install silently: the download stopped and the pack was left half-installed. The launcher now asks whether you really mean to abort, and only closes once you say yes.
- 💾 **Mods already on your PC are no longer downloaded again.** Installing a pack built on this same machine — or one whose mods you already have in another profile, another pack, the game folder or the Steam Workshop — now copies them from disk instead of re-downloading the same gigabytes. Such a mod is marked "Taken from disk — nothing downloaded" in the install list. A copy is only used on an **exact version match**: if the pack doesn't state a mod's version, or the copy on disk is a different one, it is downloaded anyway — quietly giving you a different build than the pack author shipped is worse than waiting for a download.

**Transferring a profile to another game install**
- 📦 **Drag a profile onto another install of the same version and it moves over — mods, saves and settings included.** A common situation: the game is bought on Steam (that's where the multiplayer licence lives), but a separate copy of the same version sits next to it, so Steam can be updated to a newer version without losing a setup you've been playing for months. Doing this by hand was next to impossible: some mods live in the game folder, others in the Steam Workshop, and there is no way for a player to find the latter. Now you just drag the profile onto another game in the list on the left: the launcher tracks down each mod's files wherever they are and makes an independent copy of the profile — saves, mod settings and load order travel with it. The original profile stays where it was; nothing is deleted.
- 🔎 **Before a single byte is copied you see exactly what will travel.** Every mod with the place its files live today (the profile's own, a pack, the game folder, the Steam Workshop) and its size; how much space is needed, how much is free and how much is left afterwards. Anything the target game will be missing is called out separately — an enabled War Sails DLC, for instance, since game files are never copied. **Disabled** mods raise no warnings: they don't load anyway. The copy can be cancelled, and a cancelled transfer leaves nothing behind.
- 🎯 **A transferred profile launches exactly what the original did — not one mod more.** A profile stores its mods by name, so when a mod's folder was deleted at some point, the name stayed in the enabled list. During a transfer that empty name found a mod of the same name already installed in the target game and switched itself on — Harmony and Crash Doctor, for instance, appearing in a profile nobody put them in. Such mods are now listed in the report ("files missing from the source game") and arrive switched off.
- 👯 **If the target game already has a profile with that name, the launcher asks what you meant.** Usually it's the same profile, transferred earlier. You can add a second, numbered copy next to it — «My TOR (2)» — or replace the existing one. Replacing deletes the old profile with its saves and mods, and only once the new one has arrived safely: an interrupted transfer costs nothing. Previously the list simply grew two profiles with the same name and no way to tell them apart. Cloning twice no longer produces two identical «(copy)» profiles either.
- 🛡️ **Transfers stay inside one version line.** 1.3.15 → 1.3.10 is fine; 1.3 → 1.4 is refused — 1.3 mods don't work on 1.4, and a "transfer" that quietly breaks everything is worse than a refusal. If the game version can't be read, the transfer isn't offered either.
- 🔔 **When the game updates to a new line, the launcher says so.** Steam updates the game in the same folder, so a profile full of 1.3 mods silently stayed attached to 1.4 — followed by crashes nobody could explain. A profile now remembers which build it was made for, and switching to it warns once: the game is a different version, the mods are for the old one, the shaders need rebuilding — and reminds you that the profile can be dragged onto a separate install of the old version.

**Manual**
- 📖 **The "Help" button opens the manual right on your own computer.** No internet needed: the manual ships with the launcher and opens in your browser in the language your interface is in — English, Russian, Turkish, Simplified and Traditional Chinese. It is not a wall of text: every section is a screenshot with numbered circles, and hovering a circle tells you what that button does.
- 🧰 **The pack editor has its own manual, in all five languages too.** The editor has a "Help" button of its own, and it opens the book for pack authors: the "Pack", "Mods" and "Order" tabs, where the launcher downloads mods from, how to attach a translation to a mod, how to pick a cover and how to release the finished .rickpack file. Links lead from the player's book to the author's book and back.
**Download speed**
- 🚀 **Files now download over several connections — several times faster on a throttled line.** The launcher used to pull each file over a single connection, and where a provider shapes traffic (it shapes each connection separately) that gave close to the worst possible result: around 0.1 MB/s on a line that comfortably does tens of MB/s. A file is now split into pieces and fetched over eight connections at once, written straight into the final file — no intermediate copies, no joining step. It works for our own server and for GitHub. If a server cannot serve pieces, the launcher downloads exactly as before; nothing breaks.
- ⏸ **An interrupted download continues where it stopped.** The launcher remembers which pieces are already on disk, so a broken transfer doesn't start from zero. A single failed piece retries on its own without taking the download down, and cancelling tears every connection down at once.
- ⚙️ **The number of connections is adjustable.** In the launcher's `settings.json` (`DownloadThreads`) — 1 to 16, 8 by default. Setting it to 1 turns multi-connection downloading off entirely.

**Checking mods before launch**
- 🔎 **The launcher now tells you which mod cannot load — before the game starts.** There is a class of breakage where the game dies 10–60 seconds after launch, before the main menu, leaving no crash files and no logs: a mod needs a library the game cannot find (usually ButterLib, MCM, UIExtenderEx or Harmony — missing, or simply switched off). Nothing inside the game can catch this: it loads every mod's code in one pass, before any of them starts running. The launcher now checks it itself, reading only file descriptions and executing no third-party code, and shows a list before launching: which mod, which library is missing, and which module provides it. "Launch anyway" is always there — the check isn't perfect and the last word is yours.
- 🧱 **The same check runs before a shader build.** A build assembles its own set of mods, so it can be broken where a normal launch works — which is exactly how one player's build failed over and over, compiling nothing. It no longer starts in silence: the launcher says what is missing before you spend an hour on it.
- 🩺 **If the game does crash, the report now has a "Mod load problems" section.** This kind of crash used to get "cause not determined", because there was nothing to determine — the game had written nothing. The report now states plainly which mod cannot load and what to install, and the "unrecognised signature" line is no longer printed when the cause is known. The launcher also picks up the line where the engine itself names the missing library in the game's log.

**Small things**
- 🧾 **The crash report no longer lumps every mod together.** It used to list every mod sitting in the game folder — including the ones you had switched off in the launcher, which had not loaded at all that session. Two reasons: the game enumerates everything it finds on disk, and the launcher keeps disabled mods there too (so unticking one doesn't mean shuffling gigabytes back and forth) — and the "not loaded" marker was read wrongly, so every mod came out as loaded. Now the report leads with the launcher's own list — exactly what went into the game — and the mods that were merely sitting there get their own section saying plainly that they never ran and cannot be the cause. As a bonus, diagnoses of the "you have a conflicting mod" kind no longer fire over a mod that was switched off.
- 🧱 **A crash during a shader build now shows that build's mods, not the last game you played.** The launcher only recorded the launched mod list on a normal start, so a crash mid-build arrived with the module list of whatever was played before it. The list is now written for builds too, marked as one — a build deliberately includes every mod carrying graphics, disabled ones included, because the shader cache is shared across the whole game version.
- 🛡️ **The in-game crash interceptor now works for everyone.** The module that catches mod errors inside the game and names the culprit only ever reached test builds — a normal install had nothing to attach to the game, so a crash could only be read from whatever files the game left behind. It now ships with the launcher, and a diagnosis comes through even when the game leaves no crash files at all.
- 🌐 **On the very first run the launcher asks which language you want.** It has always guessed from Windows, but the guess is wrong often enough — and someone who cannot read the guessed language will not go hunting for the setting that fixes it. A first run now opens a window listing the languages, each written in its own language (English, Русский, Türkçe, 简体中文, 繁體中文), with the guess first. One click switches the whole launcher. The window opens on top of everything else, so the question cannot get lost behind a browser or another program. Asked exactly once; the language can still be changed in Settings.
- 🔗 **YouTube and Discord links were added at the bottom of the window** — next to Telegram, Steam and Nexus.

**Games and profiles list**
- 🖱️ **Games and profiles in the sidebar can be reordered by dragging.** The order is yours now: drag a game up or down and the launcher remembers it, so the next start looks exactly the way you left it. Profiles are dragged within their own game — a profile is made for one specific installation, so it can't be dropped into another game, and the launcher simply refuses such a drop. As in the mod list, a line shows where things will land.

**Mod list**
- 🖱️ **Mods can now be reordered by dragging.** Previously the order changed only through the ▲▼ buttons, so moving a mod from the bottom of the list to the top meant dozens of clicks. Now you can just pick it up and drag it, with a line showing where it will land. The ▲▼ buttons are still there — they remain the easy way to nudge a mod by one position.
- 📐 **The mod list panel is bigger.** It used to have a fixed height and scrolled inside a small area even when there was plenty of room on screen. It now takes as much space as the launcher window allows, so long setups show far more mods at once.

**Steam Workshop mods**
- 🎮 **The launcher can now install mods straight from the Steam Workshop.** Sign in to Steam once — Settings has a new **Steam** section with a sign-in button. After that, Workshop mods download on their own — no browser, no hunting for archives. The same section shows which account you're signed in as and how long the sign-in lasts (Steam grants about 210 days), plus a sign-out button.
- 🔑 **Two ways to sign in, whichever suits you.** By QR code: open the Steam mobile app, scan it, done — no password typed at all, and the code on screen refreshes by itself so you'll never scan a dead one and be told it expired. No mobile app? There's **login + password** right next to it: they go straight to Steam for that one sign-in and are never stored, and if the account uses Steam Guard the launcher asks for the code (emailed or from your authenticator) right in the window.
- 🔗 **Installing a Workshop mod is just pasting its link.** Drop the mod's page link into the launcher (a `steam://` link or a bare numeric id works too) and it downloads and installs it. While it works, the window shows the mod's picture and title, so you can see exactly what's being installed.
- 📦 **Mod packs can now carry Workshop links.** In the editor an author pastes the mod's Workshop page link (a `steam://` link or a bare numeric id works too) and the title and the mod's picture fill themselves in, so it's obvious at a glance whether the right mod was pasted. When a player installs such a pack the launcher offers to sign in to Steam — and only if the pack really contains Workshop mods; a pack without them never mentions Steam at all. Declining doesn't break the install: those mods are simply marked "download manually" and the rest install as usual.
- 🔄 **Workshop updates are noticed even for mods you're not subscribed to.** Previously the launcher could only spot a Workshop update once Steam had already downloaded it for you through a subscription. Nobody is subscribed to a mod the launcher installed, so its updates were invisible. Now the launcher asks Steam directly whether a newer build exists and offers to update. This matters most for mods whose version number hasn't changed in years.

**Shader build**
- 🪟 **One window before a build instead of two.** The launcher used to ask "shader quality will be lowered — lower it and build?" in its own window, and open the memory window with the Start button immediately after. Two questions in a row about one action isn't informed consent, it's two blind clicks. The quality note now sits inside the build window, above the same button. With memory to spare and the quality already at minimum, no window appears at all.
- ❌ **The "build shaders or launch?" question now has a Cancel.** There was no "neither" before: press Play by accident or change your mind, and you still had to start something. A third button now cancels the launch, and closing the window counts as cancelling too.
- 🧩 **Fixed a build that died after half a minute and compiled nothing.** The launcher picks the mods carrying graphics for a build — but a graphics mod is also code, and that code needs its libraries (Harmony, ButterLib, UIExtenderEx). The libraries ship no graphics of their own, so the filter threw them out: the game started without Harmony, every mod failed on load with "could not load 0Harmony", the game closed 20–45 seconds later, and not one file reached the cache. Retrying changed nothing, and neither did switching mods off (a build ignores the ticks — the cache is shared across the whole game version). Graphics mods now bring along the libraries they need and everything they declare as required, code-only ones included.
- 🩺 **A crash during a build no longer produces an empty report.** The game left a crash folder, the launcher read it and even matched a cause — then showed a report with no cause, no game logs and a line saying there was no crash folder. The culprit was a timestamp: the game names crash folders in UTC and the launcher read them as local time, so a fresh crash landed hours in the past, before the build that caused it. The time is read correctly now, and the diagnosis and the game's own logs go into the report.
- 🎯 **Shader building is only offered where it's needed — on TOR setups.** The profile menu still carried a test entry, "Build shaders & units", shown on every profile and bypassing that check: on vanilla or a small mod set the game loaded for minutes and built nothing. Non-TOR profiles no longer have the entry at all, and on TOR it's now called "Build shaders again" — the ordinary build, simply allowed once more when the shaders are already built.
- 🧮 **The launcher now works out whether there is enough memory before the build.** The "Free up memory" window opens ahead of time and decides for itself whether the build may start: "Start the build" becomes available exactly when there is enough — instead of a refusal that only arrives after you click it. It wants 8 GB of free RAM (below that, the stage restarts the build uses to survive memory pressure stop helping) and enough virtual memory for the whole build — the page file gets its own message, because closing apps doesn't fix that one. The window shows how much is needed and how much is free, closes big apps with one click, and explains in a separate line where the rest of the memory went: Windows itself plus dozens of small processes. And if that much can't be freed, it says what to do: restart the PC, or simply play without building — the game compiles the shaders itself, the first launches are just longer.
- 📊 **The "Base shaders" bar shows real progress again.** It filled up in the very first second and stayed there for the whole five minutes the base shaders were actually compiling — with "Compiled: 0" honestly printed under the full bar. The cause: a single leftover file in the cache counted as "the shaders are already built". Now "already built" means a genuinely built cache (thousands of files), the bar moves with the build, and when there is nothing to compile it says so — "Already built" — instead of a zero counter.
- 🔓 **A "blocked" module file no longer kills the shader build.** Windows marks everything downloaded from the internet as blocked, and if the launcher was unpacked from its ZIP with Explorer, that mark stayed on its shader-build helper module. The game then refused to load it — an `Cannot load: …\RickShaderBake.dll` error box appeared and the build quietly ended with nothing. The launcher now clears the mark from its own modules and verifies the file really arrived in the game folder intact. And if the game still can't load it (an antivirus deleted it, say), the launcher closes the error box itself and explains in plain language what happened and what to do, instead of "Game closed".

## 1.2.3

**Display & settings**
- 🌍 **Five interface languages: English, Russian, Turkish, Simplified Chinese and Traditional Chinese.** Pick one in Settings and it applies instantly — crash explanations, hints and install windows all come with it. You can still add your own: the files live in the `Lang` folder next to the launcher.
- 🌍 **The launcher's language now applies everywhere, even if you never picked one by hand.** On Russian Windows the launcher switches itself to Russian — but everything it puts into *content* still treated your language as English until you went into Settings and chose one explicitly. So a pack's description opened in English even when the pack had a Russian one, a mod's Russian translation wasn't offered under "Our mods", a pack generated from a profile was stamped English, and mod descriptions were fetched in English. All of that now follows the language the launcher is actually shown in. Pack languages are also matched case-insensitively — a pack authored with "RU" is no longer treated as a different language.
- 🔎 **"Find games" no longer scans every drive.** Detecting Bannerlord installs used to walk whole drives — slow on large or slow disks. Now the launcher checks the known places first: the Windows registry, Steam/Epic/GOG libraries, store records and the usual install paths — and finds the game almost instantly. If you keep several versions in non-standard folders, a separate **"Search all drives"** button does a full walk (it also runs automatically if nothing turns up in the known places).
- 🪟 **You can minimize the launcher while shaders build — and watch progress on the taskbar icon.** Building takes a long time, and its screen used to fill the whole launcher, so the title-bar minimize button was out of reach. The build screen now has a **"Minimize"** button: tuck the launcher away and keep working while shaders compile in the background. And the launcher's taskbar icon shows a progress bar, so you can see the build is running and how far along it is without restoring the window (if something goes wrong, the bar turns red).
- 🖥️ **Fullscreen no longer gets stuck in a window after a mod's "restart" or after a crash.** Some mods (e.g. RTS Camera Universal) restart the game themselves once enabled — and on such a self-restart it sometimes fails to re-grab fullscreen and starts windowed. The same happened after a crash: the game left "windowed" in its settings, and the next launch opened in a window even though you changed nothing. Now, if the game dropped to a window not by your choice (a mod self-restart or a crash), the launcher restores your fullscreen mode and resolution — and **remembers** them, so the mode comes back even if you restarted the launcher itself between the crash and the next launch. And if you **deliberately play windowed** and exited the game normally, your choice is left completely alone.

**Stability & diagnostics**
- 🧯 **If the game crashes during the shader build, the launcher no longer stays silent.** The build path never ran crash diagnosis before: the game could close by itself on a heavy scene (e.g. loading all the troops) and the launcher only showed a bland "Game closed" with no explanation. Now, if the game vanishes mid-build and you didn't stop it, the launcher shows a plain message that it was a crash (not a normal finish) and — if crash files were left — opens the same crash-diagnosis window it shows after a normal launch.
- 💾 **Cancelling the shader build no longer throws away the base shaders it already built.** The build runs in two stages: first the base shaders (needed just to launch the game), then the full one (troops and NPCs). Previously, once the base shaders were done and the full stage had begun, pressing "Cancel" closed the game too abruptly and truncated the cache write to disk — so the next build recompiled the base shaders from scratch. Now, on cancel, the launcher lets the game shut down cleanly and save everything compiled so far (the base shaders included) — the screen shows "Saving shaders, don't close" while it does. The next build picks up where it left off instead of starting over.
- 🩺 **System check before building shaders.** For TOR it's critical that everything is configured before the shader build. The launcher now checks the things that most often make the build crash or freeze the PC: the GPU timeout (TDR), page file, free disk space, Hardware-Accelerated GPU Scheduling (HAGS), a pending Windows restart, the Visual C++ and .NET Framework runtimes, plus Game DVR. If something's wrong it shows a plain-language window with a **"Fix"** button (done right from the launcher where possible, asking for administrator rights, with an undo). If all is well the window never appears and the build starts straight away.
- 🔎 **Plain-language crash diagnosis instead of the game's error wall.** If the game crashes, the launcher reads the crash files and explains in human terms what went wrong and what to do: out of memory, a GPU timeout during the shader build, a corrupt shader cache, a mod conflict, and so on. The cause database comes from Crash Doctor (hundreds of signatures in five languages) and ships fresh with each launcher build; if Doctor is installed, the launcher also reads its diagnosis (read-only — it never changes or touches Doctor's files).
- 🛡️ **Catching crashes from inside the game — even when it leaves no crash files.** Previously the launcher could only diagnose a crash from the files the game wrote AFTER it fell over — and a hard crash often leaves none, so there was nothing to show. Now, for the duration of play, the launcher drops a small catcher module right into the game (it loads early and is **hidden from the mod list** — the game won't flag it as a "new module"). It catches errors in mods' code at the moment of the crash, works out the culprit mod, and writes the diagnosis to its own file — which the launcher reads after the game exits and shows you: what the error was, which subsystem, and which mod caused it. The module only observes and records — it changes nothing in the game and is removed from the game folder after the session (and if a crash cut the session short, it's swept on the launcher's next start). **Importantly, even with Crash Doctor disabled**, the game now closes cleanly after such a crash — no full-screen freeze — and the launcher shows the diagnosis right away. You can send the finished report to us as one archive on **Telegram or Discord** — the links are right inside the report. (This catches .NET code errors; hard video-driver crashes are still diagnosed from the crash files and via Crash Doctor.)

- 🔓 **Launching no longer fails with "Access to the path … is denied".** Before launch the launcher temporarily swaps the game's Documents folder for its own — and if something was holding that folder at that moment (OneDrive syncing, an antivirus scan, an open Explorer window, a game process still shutting down), the launch died with a raw system error. It now retries calmly a few times, and if the folder still isn't released it tells you in plain language what to close.

**Shader building**
- 🏁 **The build finishes the job by itself — however many restarts that takes.** The number of stages used to be capped, so on a memory-tight PC a big build could stop with the last few percent unbuilt and you had to start it again by hand. The launcher now runs as many stages as needed and stops only if the build stops moving at all. It also no longer restarts for a short tail of remaining items — grinding out the last hundred slowly beats a restart that costs more than they do.
- 🧠 **Low memory is now headed off, not cleaned up after.** The launcher watches memory during the build and ends a stage cleanly **before** the compiler starts failing, then waits for Windows to actually hand back the closed game's memory before starting the next one. Compiler error windows, if any still appear, are dismissed instantly — you won't see them.
- 🧾 **Only measured numbers in the progress line.** The build screen shows how many shaders are built and which item out of how many is being processed. The old "about N shaders left" estimate is gone: nobody can know in advance how many shaders the remaining items need, and the figure swung by an order of magnitude.
- ✅ **The build's verdict tells the truth.** If a build stops early but did build something, it says exactly that — how many files and megabytes reached the disk. Everything built is saved, and the next run continues from there instead of starting over.
- 🛟 **Running out of memory mid-build no longer kills the game — the build moves to the next stage instead.** When the shader compiler reported it was out of memory, the launcher used to retry a few times and the game went down anyway, taking everything compiled since the last cache save with it (that cost us 25 minutes of work once). The first such message now ends the stage cleanly, saves what's built to disk, and the build carries on in a new stage.
- 🩺 **A plain-language explanation instead of an empty crash report.** That failure leaves no .NET error and no game crash folder, so the report came out blank — "cause unknown". The launcher now reads its own build log and says it outright: the build ran out of memory, and what to do (raise the page file **and restart the PC** — a new size does nothing until you reboot; close the browser and Steam; just start the build again — it continues from where it stopped).
- 🧩 **The build no longer hits a memory wall — it runs in stages, by itself.** The engine only returns the memory it spent compiling when the game closes, so on a 16 GB PC a big build (TOR) simply couldn't fit in one run: it used to drop to "one item at a time" and crawl for hours. Now, when it reaches the limit, the launcher closes the game cleanly (everything built is saved), starts it again and **carries on from the same place** — the screen just says "Stage 2 — restarting the game and continuing the build, please wait". Nothing to click, no progress lost. PCs with memory to spare still build in a single stage and never see the stage caption at all.
- ↩️ **An interrupted build continues instead of starting over.** If a build was stopped (or a crash ended it), the launcher remembers which items are already built: the next run skips them and continues the counter from there rather than from item one. It used to look like everything had been lost. The list clears itself when a build completes, and when you delete the shaders.
- 🧮 **The build now tells you honestly what it produced.** It used to say "Done!" whenever it finished — even when not a single shader had reached the disk — and marked the version as built. The launcher now measures the cache folder before and after and reports the result: "N new shader files (X MB) added". If nothing was added it says so, and does **not** mark the version as built (the Build button stays). It also explains the common case: a mod set with no graphics mods has nothing to compile — the game already ships those shaders, and that is not an error.
- 🐢 **The build no longer drives the PC into a memory wall.** Batches of items used to be fed to the engine almost back-to-back, so it never got to release what it had loaded, memory crept up, and on a 16 GB PC the build hit the ceiling and slowed to a crawl. The pause between batches now adapts to free memory: plenty of headroom → full speed, tight → give the engine time to let go, and in a really tight spot it briefly holds off feeding (but never freezes — the build always keeps moving).
- 🧹 **Items with no usable model no longer slow the build down.** Before feeding an item, the launcher checks that it actually has a mesh with materials — empty ones are skipped and remembered so they don't get in the way next time. Only a shader warm-up is skipped; no mod data is ever skipped.
- 🧯 **One bad item no longer takes a whole batch with it.** If a batch of items errors, the launcher retries it one item at a time — the bad one is skipped and remembered, the rest build normally (previously the whole batch was lost).
- 💾 **The page file suggestion now follows your free disk space.** For a TOR build on 16 GB of RAM the old 40/60 GB wasn't enough — the build ran into the memory ceiling. On machines with little RAM the launcher now suggests 60/80 GB when the drive has room, and still 40/60 when space is tight. Nothing changes on PCs with plenty of RAM.
- ⚡ **A new light build method — gentler on the GPU and memory.** The build used to load a heavy battle scene with all the troops, and the spike in video memory often crashed weaker GPUs and stalled. Shaders are now built directly through the engine's preloader, with no battle: it walks every item and unit and builds each one's shader. The method is universal — it works not just for TOR but for any large mod set (there's a **"Build shaders & units"** entry in the profile menu).
- 🧠 **The build adapts to your memory.** While it runs, the launcher watches free RAM and the page file and changes the load on the fly: on a powerful PC (32 GB) it builds in big chunks and fast; on 16 GB it goes more carefully and slower but reaches the end. If memory runs really low it throttles so the game won't crash, and says so on screen.
- 🧹 **Free up memory in one click before the build.** If your PC is low on free RAM, the launcher shows a window before the build listing the apps using the most memory (browser, Steam, Discord, …) and lets you close them right there with one button — the row disappears and free memory climbs live. System processes and the game itself can't be closed. This keeps the build from running out of memory because of background apps. If there's enough free memory, the window never appears.
- 📊 **You can see system resources right during the build.** The build screen shows live gauges (updated every second): physical RAM, committed memory (RAM + page file) and free space on the shader-cache disk. The bars shift from green to amber to red as pressure rises — so you can see at a glance if the PC is at its limit.
- ⚠️ **A warning when memory may not be enough.** If the build includes large mods and the PC has less than 16 GB of RAM, the launcher warns you up front: the build will be slow, some shaders may finish compiling later in-game — and suggests closing the browser and Steam to free memory.
- 🧯 **Shaders the game chokes on no longer sink the whole build.** If a shader can't be built because memory is short, the launcher skips it (it'll compile later in-game) instead of spinning forever. And if a specific item hard-crashes the game, it's identified on the next run and skipped so the build can reach the end.
- ✅ **When the build finishes, you can see it's done.** The build window used to just close — which looked like a crash. Now, when it finishes, a green banner "Done! Shaders are built — ready to play" appears with **"Launch game"** and **"Close"** buttons: the window stays until you click one.
- 🎯 **"Rebuild your shaders" no longer pops up because of code-only mods.** The rebuild hint used to appear on any change to the mod set — even when you just enabled or disabled a mod with no graphics (Crash Doctor, RTS Camera Universal, a translation). Such mods add no shaders, so there's nothing to rebuild for them. The hint now appears only when mods that actually ship graphics and shaders have changed.

**Mods**
- 🖼️ **The download window shows what's being downloaded.** The mod's picture from its page appears next to the title, and the bar now moves during extraction too — it used to sit at 100 % while a large archive unpacked in silence, which read as a hang. When everything is installed the window shows a green tick and says you can close it, hiding the list of steps so the result is unmistakable. If something failed, the steps stay on screen — that's where the reason is.
- 🔗 **Nexus downloads work with the redesigned site.** Nexus rebuilt its mod pages and the download button is gone — the file is served differently now. The launcher understands that and tries several routes in turn until it has the file, so downloading by link works again with no manual steps. The file's name is taken from the server in whatever form it sends it.
- 🧯 **If a mod can't be copied completely, a clear message instead of a silent half-copy.** Installing a mod is now all-or-nothing: if even one file can't be copied (an antivirus or the running game locking files, no permission to the folder, disk full) the install is cancelled, the half-copied folder is removed, and the launcher shows a plain-language window explaining the cause and what to do. Previously a broken, half-copied mod could be left behind that wouldn't work in-game.
- 📥 **A newly-added mod lands in the right load-order slot, not at the very bottom.** Previously a mod from an archive or a download could drop to the end of the list — and if it was a library (Harmony, ButterLib, …) it ended up BELOW everything that needs it, breaking the order. Now a new mod slots into its own zone: libraries up with the libraries, ordinary mods with content, diagnostics (Crash Doctor) at the very bottom — with its dependencies respected. Works for every install path — archive, folder, URL, dependencies.
- 🔢 **Updates are now noticed even for mods that never change their version number.** Some mods pin their version to the game (TOR and Lore-Hardcore sit on `1.3.15` forever) and don't bump it between builds, so the launcher used to miss their updates even though the files changed. There are now three ways it can tell: our own mods ship a small `release.json` next to them carrying a real, growing release number (it travels with the files wherever a copy ends up); for any Steam Workshop mod the launcher reads Steam's own last-updated time; and for everything else it compares a fingerprint of the mod's shipped files, ignoring its settings, logs and caches. An update is still only offered — nothing changes without your confirmation, and the mod's settings and saves are left untouched.

- 🎮 **The game's multiplayer module is no longer loaded into a singleplayer session.** The launcher wrongly added the official **Multiplayer** module to every launch: singleplayer doesn't need it, and loading an older save made the game complain about a "module mismatch" and list it as a "new game module". Multiplayer-only modules now stay out of singleplayer launches — and out of your mod list.

**Profiles**
- 📥 **Importing from the game now brings ALL your settings, not just saves and mod settings.** Adding a game (and the **"Import my data from the game"** button) used to copy only your saves, the mod settings in `ModSettings` and your enabled-mod list — everything else in `Configs` was lost: key bindings, game options, and the folders mods create *next to* `ModSettings` (RBM, RTS Camera, Lore-Hardcore, MissionLibrary and the like). The whole `Configs` folder now comes across. The one exception is **graphics** (`engine_config`): those are tied to your hardware and to the built shader cache, so you set graphics yourself.

**Load order**
- 🧭 **Auto-arrange is noticeably smarter.** The launcher used to know only about libraries (to the top) and diagnostics (to the bottom), and dumped everything else into a single "middle". There's now a curated load-order knowledge base of known mods grouped by category (combat, factions, graphics, map, UI, …) under the hood. On "Auto-sort" and when you add a new mod, each known mod lands in its own zone — in a validated order, not alphabetically and not at the very end. You can extend the base with your own `loadorder-catalog.json` next to the launcher data — no launcher update needed.
- 💡 **A gentle hint when the order can be improved.** If your enabled mods aren't in the ideal order, a small dot lights up on the **"Auto-sort"** button, and small **▲/▼** marks appear next to the mods themselves — with a tooltip telling you which mod is better moved up or down, and relative to which one. It's only a hint: the order still works, and nothing changes until you press "Auto-sort" yourself. Hard mod dependencies (what must load after what) are respected — the hint never contradicts them.

**Mod packs (.rickpack)**
- 🌍 **A pack now installs mods already in your language.** A pack author can attach a translation to a mod — either as a set of files laid over the mod (an overlay, usually `ModuleData/Languages`) or as a separate translation module (like `TOR_RU`). On install the launcher looks at the language you picked and installs the translation for it: an overlay is merged straight into the mod's folder, while a translation module is placed right after the base mod so its strings win. If there's no translation for your language, the plain (English) version is installed and nothing breaks. Older packs with no translations open and install exactly as before.

**Pack editor**
- 🎛 **The pack editor has been completely redesigned — comfortable even for big sets.** The whole panel used to be one long scroll, with the language switch up at the top: to fill a mod in Russian and then in English you had to scroll up, switch language and hunt for the same mod again down below — a nightmare on a 50–100-mod pack. Now the left side is a full-height mod list with **search** and drag-reorder, with **"Pack / Mods / Order"** tabs on top (the mod list steps aside on the "Pack" tab — it only gets in the way there, and the pack description gets the full width), and the language switches **right inside the mod card** via small tabs (RU · EN · …) — without losing the selected mod or your scroll position. Load order is now a drag list with an **"Auto-arrange"** button (using the same order base as the launcher). Every field has a tooltip with an example; the look picks up skins (Calradia/Parchment/Cinematic) and a font.
- 🌍 **Mod translations are authored right in the editor.** On the language you want, you enable a translation in the mod card — as an overlay (files over the mod) or a separate translation module — and point it at a source (GitHub/Nexus/direct link). The mod list shows badges for which languages already have a translation. From there, on install the player gets mods in their language automatically.

## 1.0.4

- 🧱 **Shader baking fixed** — no more endless "build shaders" loop. The shader cache could previously get split (part in the launcher folder, part in the system folder), so the game didn't see the finished shaders. Now everything lives strictly in the launcher catalog and pre-built shaders are always picked up. Old "lost" data from earlier versions is migrated back into the catalog automatically on startup.
- 📦 **Re-installing a mod pack** no longer re-downloads gigabytes: if a mod is already installed and the version matches, it's simply re-linked — no download, no extraction.
- 🗑 **Deleting a profile** now asks whether to also delete its mods from disk (except ones still used by other profiles) or keep them. Keep them and re-installing the same pack is instant.
- 🧹 Clearing the shader cache now always clears the selected version.
- 🎛 UI touches: the header shows the full build number; the "Cancel" button is now on the right; confirmation dialogs are wider.

## 1.0.0 — First version

The first public release of RickLauncher. In short, it can:

- 🎮 Find your installed Bannerlord games and launch different versions and mod sets ("builds") from one window.
- 🧩 Manage mods: enable/disable, reorder, auto-order, dependency and conflict checks.
- 📦 Install mods from an archive, a folder or a link. Share a ready mod set as a single file (`.rickpack`).
- 🛡 Your mods and saves stay separate and never mess up the game's own files.
- 🌍 Languages: Russian and English (you can add your own). Pick the language in Settings.
- ⬆ Auto-update: the launcher tells you when a new version is out and updates in one click.
- 🧱 Pre-build shaders for TOR mods ahead of time — with a progress bar.
